Detailed Description

template<typename RGB_T = RGB565>
class tinygpu::DisplayDriverParallel8RP2040< RGB_T >

RP2040 PIO/DMA-accelerated 8-bit parallel ("Intel 8080"-style) TFT display driver. D0-D7 and WR are driven by one PIO state machine (see kLcd8080WriteProgram above) instead of bit-banged via digitalWrite() - see DisplayDriverParallel8.h for the portable bit-banged version this mirrors, and DisplayDriverParallel8ESP32.h for the equivalent ESP32 LCD_CAM/PARLIO-peripheral version. DC/CS/RST stay on plain GPIO (Arduino pinMode()/digitalWrite()), same as those two.

Bulk pixel data (writeData()) is fed to the state machine via a DMA channel reading directly out of the surface's buffer - the CPU issues one DMA transfer and waits for it (and the state machine's own FIFO) to drain, rather than looping a pio_sm_put_blocking() call per byte.

Hardware constraint (PIO's out pins/side-set addressing): D0-D7 must be 8 consecutive GPIOs, D0 being the lowest-numbered - this isn't a software choice, it's how the PIO block maps its 32 general-purpose output-mapped pins. WR must be a separate GPIO outside that D0-D7 range.

Parameters
d0the first (lowest-numbered) of 8 consecutive data-line GPIOs - see the class comment's hardware constraint.
wrwrite-strobe pin - the PIO program's side-set pin.
dcdata/command ("RS") select pin.
cschip-select pin, or -1 if the panel has CS permanently tied low.
rstreset pin, or -1 if not wired up.
width/heightthe panel's addressable resolution - subclasses with a rotation concept (e.g. ILI9341Driver8080RP2040) override width()/height() themselves instead and can ignore these.
clockDivPIO state machine clock divider - the program runs at 2 PIO-clock cycles/byte, so the WR toggle rate is (clock_sys_hz / clockDiv) / 2. Default (8.0) gives roughly 7.8MHz at a stock 125MHz system clock - comfortably inside most 8080 panels' timing spec; lower it for a faster panel/wiring, raise it if data looks corrupted (a symptom of the panel not keeping up).
piowhich PIO block to use (pio0/pio1) - pick one not already fully claimed by another peripheral (e.g. an RP2040 audio driver using PIO for I2S).

◆ width()

size_t width ( ) const
inlineoverridevirtual

Current addressable panel width/height in pixels - for a driver that supports setRotation(), these reflect the current rotation (landscape vs portrait swaps them; see isLandscapeFamily()), not necessarily the panel's native/physical orientation. Callers that need to lay out content (e.g. OutputTinyGPU's scale_to_fit target, or clearScreen()'s band loop) should read these fresh rather than caching their own copy, so a setRotation() call is picked up automatically without needing separate bookkeeping.
