23/**
24 * @brief IDSIBus backend for ESP32-P4, built on ESP-IDF's DBI (command
25 * channel) + DPI (video-timing channel) split - the interface ESP32-P4
26 * exposes for DSI LCDs. A DPI panel has no address-window/RAMWR concept:
27 * `esp_lcd_new_panel_dpi()` allocates a screen-sized, DMA-scanned
28 * framebuffer up front, and `esp_lcd_panel_draw_bitmap()` writes straight
29 * into a rect of it - the continuously-running DPI bridge just scans
30 * whatever's currently there.
31 *
32 * Only a single frame buffer (`num_fbs = 1`) is used, so a write landing
33 * while that region happens to be mid-scan can tear - this driver doesn't
34 * attempt the double-buffer-plus-dirty-rect scheme some vendor BSPs use to
35 * avoid that; same tradeoff DisplayDriverSPI/QSPI already accept for a
36 * torn/partial transfer landing mid-refresh.
37 *
38 * This is a straight extraction of what used to live directly in
39 * DisplayDriverDSI before the IDSIBus split - behavior is unchanged.
40 */
